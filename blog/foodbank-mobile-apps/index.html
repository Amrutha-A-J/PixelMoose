Putting the food bank in people’s pockets

How the food bank’s booking app went from an installable web app to Android and iOS apps in the stores, built from the same code.

Once clients could book their own visits in the food bank’s booking app, the next question was where they would open it. For most of them, the answer was their phone.

Step one: an installable web app

The booking app started out as a progressive web app (PWA): a website you can add to your home screen so it opens like an app. It worked, and it cost nothing extra to run. But installing a website from a browser menu is not something most people know to do, and when people look for an app, they look in the app store.

Step two: Google Play

In August 2025 the app went onto Google Play. Clients and volunteers could now find “Moose Jaw Food Bank” in the store, install it like any other app, and get straight to booking.

Step three: Android and iOS from the same code

In December 2025 I moved both apps onto one shared setup, so the same code that runs the website also ships to Android and iOS. With proper store apps on both platforms, the PWA was no longer needed, so we retired it.

This matters more than it sounds for a small organization:

  • Every feature reaches everyone at once. A fix or a new feature in the web app goes out to Android and iOS in the same release, with no second app to keep in sync.
  • One thing to maintain. There is no separate mobile codebase, and no mobile developer to hire.
  • It’s the app people already know. The screens, wording and steps are the same as on the website, so staff can help anyone, whatever device they’re on.

What people do with it

  • Clients book, reschedule and cancel pantry visits, and see their upcoming appointments and history.
  • Volunteers book shifts and see what they have coming up.
  • Staff can check the schedule and record work on the go.

For people who don’t have a smartphone at all, there is also a phone and text booking line.

For the technically curious: how it’s builtShow
  • Capacitor shells. The android/ and ios/ projects are Capacitor wrappers that load the built React app. They replaced an earlier Bubblewrap Trusted Web Activity, which only covered Android.
  • Same store listing. The Android app keeps its original application ID so it updates the existing Google Play listing instead of starting a new one; iOS has its own bundle ID, restored automatically by the sync scripts.
  • Safe builds. The mobile build always points at the production API and fails if a localhost address slips into the bundle. The native code also replaces any insecure API setting at runtime as a final safety net.
  • Releases. Android and iOS versions are bumped together, with a changelog grouped by who the change affects: clients, staff, volunteers and agencies. Icons and splash screens are generated from one source image.
